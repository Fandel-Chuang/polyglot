# 文达运行时蓝图式调试界面设计（Web UI）

版本：v0.1（草案）
状态：可执行设计，准备立项
作者：GPT5（Infra/QA/Tooling）

一、目标与边界
- 目标：提供类似 UE 蓝图的“函数/方法级”的可缩放调试视图，不显示行号，仅以“类.方法”或“全局函数”为粒度展示节点，支持运行状态颜色编码与断点交互。
- 非目标（本期不做）：汇编/寄存器级调试、行级编辑/跳转、跨机远程调试（仍限制 127.0.0.1）。
- 默认关闭：需构建时 -g 产生 WDB，运行时以 `wenda debug` 或 `--enable-debug` 显式开启。

二、总体架构
- 编译器（-g）：生成 WDB（文件/函数/类/变量/方法层级信息）。
- 解释器（AST）：在每个函数入口/返回/异常处打钩子，发出 runtime 事件。
- 调试服务（Debugger Server）：本地 TCP/WebSocket，提供 Graph API 与事件推送。
- Web UI（浏览器）：Canvas/WebGL 渲染蓝图，响应式布局，支持缩放/平移/过滤/断点操作。

三、开关与使用
- 构建：`wenda build -g` 或 `wenda build --debug`
- 运行：
  - `wenda debug --file 程序.文达 --web [--port 9230] [--token xxx]`
  - 或 `wenda run --file 程序.文达 --enable-debug`
- 安全：默认仅绑定 127.0.0.1；可选 Token 校验。

四、蓝图 UI（不显示行号，仅函数/方法粒度）
1) 视图与交互
- 主画布：可缩放（0.25×~4×）、可平移（空格+拖拽），右下角 Mini‑map。
- 节点：
  - 全局函数：圆形节点（Global）
  - 类方法：圆角矩形节点（标题两行：类名 / 方法名）
  - 类容器（Cluster）：可折叠展开，将同一类的方法聚合
- 边：函数调用关系；当前调用链高亮加粗。
- 状态颜色：
  - 当前所在：亮黄 #FFCC00（发光/脉冲效果）
  - 已跑过：蓝绿 #28A8EA（亮度随命中次数/热度增加）
  - 未跑过：灰色 #8A8A8A
  - 断点：红色描边 #FF4D4F（函数入口断点/条件断点）
- 侧栏：过滤（仅显示当前/相邻/已跑过）、图例、搜索（类名.方法名 聚焦）。

2) 节点右键菜单
- 设置/取消函数级断点（入口断点）
- 条件断点表达式（如：`怪物.hp < 10`）
- 添加到监视（运行计数、最近时间、异常统计等）

五、调试语义映射（函数级步进）
- continue：运行至下一个“函数入口/异常/断点”。
- step into：跳入被调用函数（图上移动至目标方法节点）。
- step over：在同一类容器内过渡到下一相邻节点（不下钻）。
- finish：从当前函数返回至上层调用（回到调用方节点）。
- 函数级断点：在“函数入口”停住；条件断点在入口对表达式求值。

六、数据模型（Graph API）
- GET /graph/runtime
```json
{
  "nodes": [
    {"id":"n1","kind":"global","name":"初始化系统","visited":3,"hasBreakpoint":false},
    {"id":"n2","kind":"method","class":"玩家","name":"攻击","visited":12,"hasBreakpoint":true,"clusterId":"c_player"}
  ],
  "edges": [
    {"from":"n1","to":"n2","calls":5},
    {"from":"n2","to":"n3","calls":2}
  ],
  "clusters": [
    {"id":"c_player","title":"玩家","collapsed":false}
  ]
}
```
- 运行时事件（WS）：
  - `runtime:stopped { currentNodeId:"n2" }`
  - `runtime:visited { nodeId:"n2", delta:1 }`
  - `breakpoint:changed { nodeId:"n2", enabled:true, condition:"怪物.hp<10" }`
- 断点接口：
  - `POST /breakpoint { nodeId, enabled, condition? }` → `{ok:true}`

七、解释器对接（函数粒度钩子）
- 在函数入口/返回/异常处发送事件：
  - 入口：`runtime:visited(nodeId)`，若命中断点→`runtime:stopped(currentNodeId)` 并暂停执行
  - 返回：`runtime:visited(nodeId)`（可选统计）
  - 异常：`runtime:stopped(currentNodeId, reason:"exception")`
- nodeId 映射：由 WDB 在构建时为“全局函数/类方法”分配稳定 id。

八、性能与渲染
- 推荐 WebGL（PixiJS/Konva/vis-network）以支持大图平滑缩放。
- 优化：
  - 视口裁剪，视口外节点惰性渲染
  - LOD：缩小时仅显示图标/颜色，放大时显示文字
  - 布局缓存：用户手动拖拽后保存布局（.wenda-layout.json）

九、安全
- 默认仅 127.0.0.1；支持 `--token`；空闲自动断开；日志脱敏。

十、落地计划（里程碑）
- M1（1 周，原型）：
  - Debugger Server：`/graph/runtime` 返回静态图；WS 推送假数据
  - Web UI：节点/边渲染、缩放/平移、状态颜色、Mini‑map、搜索
  - 断点：节点级开关（仅 UI 层）
- M2（1–2 周，对接运行时）：
  - 解释器钩子→真实事件：visited/stopped
  - 断点后端：POST /breakpoint 生效；条件断点（入口求值）
  - 过滤器与类容器折叠/展开
- M3（1 周，增强）：
  - 热度映射与边加粗；布局保存；异常停住；命中计数断点
  - TUI 同步（限定缩放层级）

十二、验收标准（MVP）
- 构建 -g；运行 `wenda debug --web`，在浏览器中：
  - 能看到类容器与函数/方法节点的蓝图图
  - 颜色正确：当前在某函数、已跑过、未跑过
  - 可以在“函数级”设置断点/条件断点并命中
  - 过滤功能可降噪，仅显示“当前 + 相邻/已跑过”
